## 2. Resolved — done and verified

Both identifier problems are fixed in the working tree. Nothing is committed yet.

### 2.1 Prolific submission IDs removed from `data/smile25b_raw_data.csv` ✅

The column `Participant External Session ID` held 1,174 unique 24-character hex values,
each an exact match to a `Submission id` in the Prolific export — live keys into Prolific's
records, one per participant. The consent form promises "your Prolific ID number will be
removed from the data."

**Fix applied.** `smile25b_process_data.R` now drops the column alongside the Prolific
participant ID, before `write_csv()`:

```r
## Remove the Prolific submission ID, which also links back to participants
df <- df %>%
  select(-`Participant External Session ID`)
```

The script was re-run end to end from the Gorilla source exports.

**Verified:** 782 → 781 columns, that one column removed and no other; 10,566 rows
unchanged; a scan of all 781 columns finds **no remaining long-hex identifiers**, no
email-like values, and no free-text self-identification. The only remaining ID columns are
`Participant Private ID` (= `Gorilla_ID`, the join key) and `Schedule ID`, both
Gorilla-internal and not resolvable outside the researchers' own Gorilla account.

### 2.2 Non-consenting participants removed from `data/smile25b_openface_processed.csv` ✅

The file held 1,183 rows. Exactly 27 of them were participants who answered "No, I do not
want my data used in the research" to the debriefing item `Data_consent object-14`.
`smile25b_process_data.R` filters these people out, but `smile25b_compile_openface.R` runs
independently and never applied the filter, so their facial-behavior measurements were
sitting in a file slated for publication.

**Fix applied.** `smile25b_compile_openface.R` now builds the same non-consent list from
the Gorilla questionnaire exports and filters before writing. The script was re-run over
all 15,879 per-frame OpenFace output files.

**Verified:** 1,183 → **1,156** rows. Exactly the 27 non-consenting IDs removed, none
added. Every ID in the new file is now present in `smile25b_processed_data.csv`
(previously 27 were not).

### 2.3 Nothing downstream changed ✅

This was the thing to be careful about, so it was checked directly rather than assumed.

`smile25b_processed_data.csv` was regenerated: **same 1,174 rows, same 1,174 IDs, same 135
columns in the same order.** 129 of 135 columns are byte-identical. The six that differ are
the OpenFace columns (`AU12_scalar_*`, `AU12_binary_*`, `face_detection_*`), and they
differ by at most **4.4 × 10⁻¹⁶** — floating-point noise from summation order when the
per-frame means were recomputed, not a change in data.

Both compliance flags (`face_compliance_scalar`, `face_compliance_binary`) are
**byte-identical**, and those are what the sensitivity analyses filter on.

To rule out a borderline case flipping: across every participant, the closest any value
comes to a sensitivity cutoff (AU12 delta of 1.5 or 0.5, face detection of 0.8) is
**3.5 × 10⁻⁴** — twelve orders of magnitude above the noise. No exclusion decision can
change.

The cached `.Rds` model objects in `data/main_analysis/` and `data/secondary_analysis/`
were deliberately **left alone**. Re-running the analyses would only rewrite them with
1e-16 noise and produce a large, meaningless diff. Every reported number is unaffected.

`data/smile25b_awareness_check_pending.csv` regenerated byte-identical.

`smile25b_writing.pdf`, plus both scripts) is in the session scratchpad:

### 3.2 The videos must be destroyed, not merely withheld

The consent form commits to destruction:

> "you will be video recorded ... it will be destroyed once the research study has been
> completed."

`data/gorilla_survey/` is a symlink into OneDrive holding roughly 263 MB across eight batch
folders, plus 15,879 per-frame OpenFace CSVs derived from them.

**Open question:** does "once the research study has been completed" mean Stage 2
acceptance or publication? That sets the deletion date. Either way this is an active
obligation, and the README note should say the videos were destroyed per the consent
agreement rather than simply not included.

The derived AU12 scores are a de-identified abstraction and are fine to share.

**Note on ordering:** `smile25b_compile_openface.R` and the first 72 lines of
`smile25b_process_data.R` both read from `data/gorilla_survey/`. Once it is deleted, those
steps can never be re-run. Both shared outputs have now been regenerated from the fixed
scripts, so **the current files are the ones to keep.** Do not delete the source until
you're satisfied with them.

## 5. Reproducibility — what a reader can and cannot re-run

Worth stating plainly in the README, because the pipeline does not run end to end from a
clone.

| Script | Runs from the public repo? | Why |
|---|---|---|
| `smile25b_run_openface.R` | No | Needs the videos (destroyed) and a local OpenFace install |
| `smile25b_compile_openface.R` | No | Needs the per-frame OpenFace output *and* the Gorilla questionnaire exports (for the consent filter) |
| `smile25b_process_data.R` lines 1–76 | No | Needs the Gorilla exports + Prolific demographics in `data/gorilla_survey/` |
| `smile25b_process_data.R` lines 79–389 | **Yes** | Reads the shipped `data/smile25b_raw_data.csv` |
| `smile25b_main_analysis.R` | **Yes** | Reads `data/smile25b_processed_data.csv` |
| `smile25b_secondary_analysis.R` | **Yes** | Same |
| `smile25b_supp_analysis.R` | **Yes** | Same |
| `writing/smile25b_writing.qmd` | **Yes** | Reads processed data + cached `.Rds` |

The shared entry point is `data/smile25b_raw_data.csv`; everything from cleaning onward
reproduces. The two irreproducible stages are exactly the ones that touch video and the
Prolific-linked source exports — which is the expected cost of honoring the consent terms.

Consider adding a "reproduce the paper from a clean clone" section with the run order, and
recording R and package versions (`sessionInfo()` dump or `renv.lock`).

## 8. Pre-public verification sweep

Run these immediately before flipping visibility. The identifier checks pass now; the
hygiene checks in §3.3 will not pass until that cleanup is done, and the git-history
check is a known accepted exception (§3.1).

```bash
# No 24-hex Prolific identifiers anywhere in the tracked tree
git grep -nE '\b[0-9a-f]{24}\b' -- data/ | head

# Expected row counts. Use a CSV-aware count, not `wc -l` -- the free-text
# Purpose/Concealment fields contain embedded newlines, so `wc -l` overcounts.
Rscript -e 'cat(nrow(readr::read_csv("data/smile25b_processed_data.csv", show_col_types = FALSE)), "\n")'      # 1174
Rscript -e 'cat(nrow(readr::read_csv("data/smile25b_openface_processed.csv", show_col_types = FALSE)), "\n")'  # 1156

# Prolific submission ID column is gone
head -1 data/smile25b_raw_data.csv | tr ',' '\n' | grep -n 'External Session'   # no output

# No tracked symlinks, .DS_Store, or R history
git ls-files -s | awk '$1=="120000"'
git ls-files | grep -Ei 'DS_Store|\.Rhistory|\.Rapp\.history'

# The source directory is untracked and ignored. Note that `git check-ignore`
# reports nothing while the symlink is still tracked -- tracked files override
# .gitignore -- so run this only after untracking it.
git ls-files --error-unmatch data/gorilla_survey 2>/dev/null && echo "STILL TRACKED"
git status --short data/gorilla_survey                      # no output
```
